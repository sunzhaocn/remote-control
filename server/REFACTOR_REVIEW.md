# 后端检查与重构（0.3.12 配套）

本地重构阶段没有访问或部署线上服务器。之后按用户指示，2026-10-16 已部署此二进制并完成真实存储与公网信令检查，详见文末。客户端协议字段保持不变，现有 0.3.11 客户端可以连接此后端。

## 修复与职责拆分

- `api/validation.go`：CONNECT 先检查 IP、设备、目标的失败封禁，再计算密码哈希；封禁期内正确密码也不能绕过。只有验证失败累计计数，注册和心跳不累计。Redis Lua 把失败计数与到期时间作为一次操作，并修复旧的无到期时间计数。
- `api/pairing.go`：固定和随机 ID 使用同一所有权检查；正在发布的哈希、设备所有者、随机有效期合成不可变记录。CONNECT 验证该记录并在建立会话前再次核对记录和连接，防止使用另一个凭据对应的设备。
- 随机 ID 的 owner/hash/TTL 原子写入，清理只删除相同 owner 的记录，防止旧凭据到期后误删他人重新占用的 ID。存储失败时不替换原来的活动凭据。Redis 操作移出所有会话共用的锁。
- `api/session.go`：确认和确认超时共享原子状态转换；已确认的会话不再被旧确认计时器撤销。未确认的会话禁止转发 SDP/ICE/控制信令，重复确认不重置会话。INCOMING 发送失败立即释放会话。租约按被控设备 ID 绑定，避免改配对 ID 后为同一被控设备取得第二份租约。
- 双方 CONFIRMED 按稳定的连接写锁顺序写入，之后才允许并发转发 SDP/ICE；这是服务端消息顺序保证，不宣称现有手机已复现消息反超。任意一侧 CONFIRMED 写入失败即撤销并释放租约，避免保留半确认会话。主动撤销先移除会话，再通知对端，不让慢连接阻塞撤销生效。
- 已被新 WebSocket 替换的旧连接不能继续发布凭据或处理新的信令。

## 部署兼容与存储边界

不新增数据库表或列，不要求 schema 迁移。继续使用现有 `devices`、`fixed_ids`、Redis `pair:`、`pair-owner:` 和 `limit:` 结构。租约仍用 `lease:` 前缀，其标识从配对 ID 改为被控设备 ID；更新后旧租约按原 30 秒 TTL 自然到期，不需要删除 Redis 数据。重启后客户端按既有流程重连并重新发布凭据。

这仍是单信令进程设计：在线连接和会话存在本进程内存，不能据此宣称支持多副本横向部署。发布 mutex 串行化本进程发布；PostgreSQL transaction advisory lock 串行化同 ID 的持久化检查。PostgreSQL 和 Redis 没有分布式事务：Redis 随机占用成功而 SQL 失败时可能留下直到 TTL 到期的占用，但不会激活新凭据或把请求路由给其他设备；SQL 提交成功但响应中断时重试可以重新发布。固定 ID 转换后的同所有者随机键清理失败时，残留键自然到期且不参与活动凭据验码。

现有凭据和签名算法没有变化，未写出凭据、验证码、TURN 密钥或服务器密码。

## 可信反向代理

新增 `TRUSTED_PROXY_CIDRS`，以逗号分隔明确的代理网络，默认只信任 `127.0.0.0/8,::1/128`。只有 TCP 对端位于该白名单且 `X-Real-IP` 是单个有效 IP 时才采用它；其他请求始终以 TCP 对端计数。Compose 已显式传递此环境变量。

现有 host Nginx → `127.0.0.1:18080` → Docker 后端使应用看到 Docker 网桥网关。部署时已通过后端网络命名空间中的连接记录，确认对端为 `::ffff:172.19.0.1`，因此运行环境的 `TRUSTED_PROXY_CIDRS` 设置为 **`172.19.0.1/32`**。仅回环绑定的后端端口和 Nginx 覆写 `X-Real-IP` 已核对，真实 Redis 中也验证了隔离测试 IP 独立计数。网络拓扑改变时必须重新验证这个单个地址，不能放宽到整个私网或 `0.0.0.0/0`。

## 验证边界

测试使用 miniredis 执行 Lua 和 TTL/并发行为，SQL 发布错误路径使用仓储替身；CONFIRMED 顺序和发送失败清理通过本机 httptest WebSocket 验证。它们验证本地策略、消息入口与状态转移，**没有连接真实 PostgreSQL/Redis，也不构成线上存储或双手机验证**。Windows 环境未提供 C 编译器/CGO，`go test -race` 无法运行；并发用例已在普通 `go test` 中执行，不能称 race detector 已通过。具体测试清单、build/vet 结果和二进制哈希见 `dist/BUILD_REVIEW.json`。

## 后续线上验证（2026-10-16）

仅更新信令容器，PostgreSQL、Redis、Coturn 保持原容器和启动时间。公网 TLS 健康 204；P-256 注册、注册幂等、WebSocket 认证、随机/固定 ID 在线和离线所有权、同所有者随机转固定、未确认禁止转发、双端确认、SDP/ICE/控制信令、心跳租约、拒绝与撤销后的立即重连、旧连接替换共 8 项检查通过。另以 SSH 隧道和预先确认无状态的保留测试 IP 验证 10 次失败封禁、正确码不能绕过、同一 IP 的新设备与新目标仍能连接，共 2 项检查通过；真实 Redis 中 IP/设备/目标计数均为 10 且 TTL 正常。

临时设备先按 UUID 和公钥 SHA-256 核对，再定点删除 7 条设备记录及其配对、租约和限流数据，未扫描删除用户数据。TURN UDP/TCP/TLS 均完成公网分配和双向数据回传。运行二进制 SHA-256 与本地构建一致。部署、探针、清理回执见 `../artifacts/DEPLOYMENT_0.3.12.json` 及其证据引用；回滚见 `../docs/DEPLOYMENT.md`。这些检查覆盖实际存储与信令路径，SDP/ICE 内容为合成探针，手机触控、音画同步、P2P/LAN 和媒体延迟仍由用户测试。
