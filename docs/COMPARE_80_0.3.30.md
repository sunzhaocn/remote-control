# 临时80%固定分辨率对照版

用户要求取消动态模糊，仅保留原画面80%后与0.3.30比较。这里继续按宽、高各保留80%实现，约为原像素数的64%；不是可测量的主观画质80%或固定码率80%。

对照版取消交互期间随资源档降低分辨率：操作、静止、视频、编码精修、旧保护档均固定同一80%宽高。例如1080×2400始终约864×1920，不在按返回、滑动或播放视频时切换像素档。原生自动分辨率/帧率适配仍关闭；30fps最高目标、VSync、拥塞控制、码率自适应、队列保护与有限文字补帧保留。也就是说，网络不足时仍可能降低码率或丢帧，不承诺主观画质或延迟恒定。

对照是独立build type `compare80`：包名 `com.simplerc.app.compare80`，版本 `0.3.30-compare80`，桌面名称“SimpleRC 80% 对照”，无障碍服务名称也带“80% 对照”。普通debug/release默认关闭该开关，原先交付的0.3.30安装包保持原文件和SHA-256，可并排保留。当前主版本仍为0.3.30，不将临时对照版替换为正式默认策略。

## 安装比较

两部手机都安装 `../artifacts/SimpleRC-0.3.30-compare80.apk`，打开“SimpleRC 80% 对照”，使用新策略后连接。因是独立应用，设置/连接凭据与原版分开，需要为新应用重新授予无障碍、屏幕共享和需要的悬浮显示权限；不影响原版数据。测试前先断开原版会话、停止原版被控待机，测试时只保持一组连接；建议用临时版新生成的随机ID。

对照相同手机、网络、页面/视频、音频开关，比较滑动流畅度、响应延迟、停止后的字体和持续视频。诊断应显示“80%固定对照：操作/静止/视频统一分辨率”；若切到默认兼容策略则不走本次固定80%管线，因此比较时两端都使用新策略。

组件声明使用完整类名，确保独立包名下前台服务类型和实际实现一致；打包后检查三个服务的foregroundServiceType。构建：`./gradlew :app:testDebugUnitTest :app:testCompare80UnitTest :app:assembleCompare80 :app:lintCompare80 :app:lintDebug --no-daemon`。校验：`python -X utf8 artifacts/verify-compare80.py`，回执 `../artifacts/BUILD_0.3.30-compare80.json`。

普通配置和对照配置分别运行同一套测试，并新增固定80%、高分辨率、精修不改像素和实际Buffer在交互时不缩小的检查。未安装或操作用户手机，未做双机画质/延迟实测；未部署后端，AAR和原生库不变。
