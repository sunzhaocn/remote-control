# 0.3.4 修复说明

本轮先复现 0.3.3，再修复；基线记录见 DEVICE_TEST_0.3.3.md。用户明确授权两台 USB 手机测试、服务器后端更新、15 秒截止和界面/通知/音频/亮屏改动。APK 不上传服务器。

## 已确认原因

1. 控制消息用两台手机墙钟相减且要求年龄非负；OPPO 领先约 0.8–1 秒，合法操作被拒。改为会话内单调时间校准，保留 2 秒时效和测量误差上界。
2. 恢复后旧 controlEnabled 门禁未正确开放；信令、媒体、租约和时钟就绪现在分别核对，恢复音频意图后重开操作。
3. REVOKED 回调再次发送 REVOKE，旧会话报 SESSION_INVALID。现在远端撤销不回发，服务器重复撤销幂等。
4. 验证限流客户端倒计时阻止被控注册；只限制控制端验证，被控注册和心跳独立。服务端失败计数覆盖所有统一验证失败，正常认证请求不计数。
5. 等待确认期间租约没有续期，确认接受又没有补续；租约失效后媒体未停止。现在等待续租、接受原子续租、失效双端撤销并清理。
6. onTrack 默认解除静音；本机许可变化不权威同步。现在初始静音、版本化音频确认、本机关闭立即停采集/脱轨并双端同步，恢复不会用旧 ACK 开启声音。
7. 输入布局和普通页面在大字体下挤压。现在凭据放弹窗，长字段横向编辑不截断，主页面仅溢出时可滚动；共享触控独立。
8. 导航初次布局宽高为零被缓存为左上位置，展开遮挡状态区。现在等有效测量才初始化到右下，展开和旋转约束实际边界。
9. 音频原停止函数在轨道脱离失败后跳过关闭录音；现在每一步独立清理，任何失败不回成功 ACK。启动失败也关闭录音并释放本次资源。

## 推测及证据边界

- 历史“建立媒体连接超时”的唯一原因未证明。SDP/ICE 回调已修复；序号分配/发送竞态静态存在，基线没有 SEQUENCE 拒绝日志，不能称其为该次唯一根因。
- 0.3.3 具体租约失效时间受等待确认耗时影响；代码证明续约缺口，缺少取得锁的完整时间线，具体过期间隔属推测。
- 新版测试的两次“无障碍服务已停止”与被控端执行页面结构读取紧邻。Android UiAutomation 默认抑制无障碍服务；改为不读取被控结构后连接稳定。此为工具干扰，不删正式安全停止逻辑，也不能据此声称厂商后台已完全解决。

## 修改范围与影响

Android SessionCoordinator/SessionMedia、PeerClock、QualityStats、三个前台服务、ForegroundSupport、权限门禁、MainActivity/ViewModel、状态和 Compose 页面/导航；后端 api/server.go、config、protocol。增加 WAKE_LOCK，仅维持 CPU/活跃会话显示，不修改全局超时，不唤醒手动锁定手机。调试质量日志只含计数/RTT/丢包，无地址、凭据、音频内容。

Android debug 与 Go build/vet 构建通过；后端已部署，健康 204，服务器 APK 哈希不变。实际双机结果和本地 APK 哈希见 STATE、DEVICE_TEST_0.3.4。构建成功不等于全功能通过。

## 仍需复查

完整旋转采集同步、H.264 排序、动态质量、完整 PeerConnection 重建/媒体停滞、单应用范围检测、SDP 指纹额外绑定、180 天固定 ID 回收、跨公网 TURN 和全部键盘/坐标组合仍有缺口。不能承诺永不被系统杀死、任意音源可捕获或所有切网都成功。
