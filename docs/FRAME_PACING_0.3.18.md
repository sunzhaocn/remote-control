# 30帧采集调度与垂直刷新显示（0.3.18）

## 修改依据与结果

原实现中ScreenCapturerAndroid忽略startCapture的FPS参数，采集纹理到达即向后提交；VideoSource和sender主要在后段限制帧率。显示端虽只保留最新待显示帧，但解码帧一到就唤醒EGL提交，没有明确的VSync节奏；应用策略还会在30/60及弱网20之间调整目标。这些静态事实支持改进调度，不代表已经测出了用户手机卡顿的唯一原因。

新策略把采集与发送目标统一为最高30fps，取消健康后升60及弱网主动改20的分支；压力优先调整码率和像素。三态继续控制画质：交互长边960、媒体原屏75%、静止请求原屏清晰度，仍有设备和网络安全档。三个状态统一MAINTAIN_FRAMERATE，避免状态切换又引入不同帧率偏好。真实来源停帧、网络不足或编解码器阻塞仍可能低于30，不能把目标当实测值。

## 采集：在取得纹理前安排时刻

SurfaceTextureHelper新增显式启用的setCaptureFrameRate，只有新策略的投屏helper启用；解码器使用的helper及默认策略维持未限速路径。SimpleRcCaptureScheduler在updateTexImage之前判断绝对时隙，提前到来的生产通知合并为一个延时唤醒，到点再取得可用的新纹理。没有缓存一串旧VideoFrame，不长期占住旧纹理来等待时刻，不增加逐帧CPU像素转换。

时隙按30fps的单调时钟相位递进，Handler的毫秒舍入不会逐帧累积成越来越低的FPS。若线程长时间阻塞，跳过错过的时隙，一次只取当前画面，不连续补交历史帧。没有新画面就没有调度循环，静止清晰补帧仍按0.3.17的有界请求执行；stopListening/dispose取消旧计时器。

## 显示：EGL线程上的VSync

EglRenderer在自己的EGL Looper创建Choreographer，通过SimpleRcVsyncScheduler请求垂直刷新回调；绘制不搬到应用主线程。30fps在60/90/120Hz稳定时分别每2/3/4次刷新最多提交一张新画面；根据当前显示刷新率限制最小提交间隔，迟到一帧后也不靠紧接着显示下一帧来追赶。刷新率变化通过系统显示监听更新。等待期间新帧替换旧待显示帧，回调到点只处理最新一张，仍保留上版的末帧，不按年龄丢弃最终更新。没有新帧不重复绘制或常驻唤醒。

Android11及以上对Surface设置30fps视频源提示，帮助系统选择合适的显示模式；不强制可能黑屏的非无缝模式切换。Android10仍有EGL线程VSync调度，跳过不支持的Surface API。该提示不保证系统一定选择目标刷新率；144Hz等非30整数倍且系统不切模式时，刷新次数会按4/5交替，不能承诺所有面板都做到完全相同间隔。

Surface销毁时移除VSync回调，重建时将最新待显示帧重新绑定到新的唤醒状态；清屏后没有待显示帧也清除虚假的“已有任务”标记，防止未来新帧再也无法触发显示。完整释放取消回调；旧EGL线程的待执行任务不得操作重新初始化后的EGL资源。

## 统计与压力策略

诊断保留总显示前等待，增加其中刷新调度等待的分项；只扣除计划等待部分后将额外排队反馈给压力策略。实际回调迟到、绘制、换缓冲和编解码耗时仍单独保留。不会把正常等待下一次刷新误作CPU积压，从而连续降低画质。GPU提交次数仍只表示完成swap提交，不能冒充物理屏幕呈现时间或触控端到端延迟。

## 验证边界与安装

- 应用单元测试覆盖固定30目标、时隙相位、舍入漂移、60/90/120Hz对齐、144Hz有界间隔、线程停顿不追帧、压力统计扣除计划等待、Surface清屏/重建后唤醒恢复，并保留触控和三态回归。
- `SCHEDULER_TEST_0.3.18.json`的16项检查加载构建AAR中的实际调度器字节码，使用确定性的Handler/Choreographer行为桩；另有10项实际capturer Java行为桩和8项AAR队列回归。均不模拟真实GPU或手机屏幕。
- 固定上游三份补丁可重放；四ABI原生库与25个内部音频类和0.3.17一致。版本0.3.18/versionCode21，签名保持兼容。
- 两端覆盖安装 `artifacts/SimpleRC-0.3.18-debug.apk`，选择“新策略”后重新连接。后端和控制协议未更改，无需部署。

本轮未安装或测试手机，不能声称真实卡顿已经消失。实测应分别检查被控端本机滑动时的远端视频、远程滑动、持续视频播放与暂停清晰末帧、横竖屏/后台Surface重建，并对比实际采集/编码/渲染帧率。输出尺寸切换仍可能触发厂商编码器重配置，若实测停顿集中在画质切换点，需要继续针对该路径调整；本轮调度不会绕过系统温控或制造缺失的真实画面。

依据：[Android Choreographer](https://developer.android.com/reference/android/view/Choreographer)、[Surface帧率提示](https://developer.android.com/media/optimize/performance/frame-rate)。
