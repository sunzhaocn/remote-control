# 0.3.30 无操作时静止和视频统一约90%分辨率

按用户“双方都没碰屏幕时，静止画面和视频只压缩正常画面10%”执行。本次将10%解释为屏幕宽、高各降低约10%，并非码率降低10%或可测量的主观画质损失10%；两边各90%对应约81%的原像素数，尺寸仍按编码需要取偶数。

## 输出规则

- 没有有效交互提示时，静止、视频、短动画统一采用原屏宽、高约90%。不等待媒体分类、静止精修确认、带宽试升或旧保护档恢复。
- 此状态忽略旧网络/设备像素档、试升像素档、2400/3200长边上限和静止原屏放大档，避免二次缩小或静止/视频之间尺寸跳变。比如1080×2400约输出970×2160；2160×3840约输出1944×3456，偶数取整有至多2像素误差。
- 已识别的控制端操作仍进入原交互策略，按实际资源压力允许降低分辨率。移动提示最长220ms、导航/点击提示最长350ms，原始时钟有效期、乱序/重复拒绝保持；到期直接恢复90%，视频帧和ACK不能续期。
- 编码码率上限、带宽估计、真实拥塞降码率、编码队列丢帧和30fps最高目标仍有效。保持90%分辨率不保证窄带时编码细节也固定90%，也不保证设备过载时永不掉帧。
- 静止文字的有界补帧和8Mbps预算试验保留，但仅作同一90%尺寸的编码细化，不再切原屏或3200长边档。字幕/视频自然出帧不触发像素降档。
- 诊断和senderPolicy反馈增加“无操作固定90%分辨率；码率自适应”，继续列出目标/最近编码/对端解码尺寸。内部保护档仍可用于下一次交互，不能压低无操作输出。

## 触摸识别边界

现有链路识别控制端远程操作，不能声称已经无侵入地监听两部手机在所有应用中的全部物理触摸。Android11没有通用的无影响全局触摸回调；Android新版本的AccessibilityService运动事件监听也会改变事件分发，不适合直接接入。未识别到的被控端本地触摸同样保持90%，不以画面变化推断触摸、不拦截系统触摸，不影响被控端应用的正常输入。

官方依据：[AccessibilityService.onMotionEvent](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onMotionEvent(android.view.MotionEvent))。本次未启用该监听、触摸探索、全屏输入遮罩或新的无障碍事件钩子；无障碍、悬浮导航、控制端返回保护、亮屏生命周期和权限均未修改。

## 验证和安装

覆盖旧低画质档下的静止/视频固定尺寸、导航提示到期和持续视频不续期，以及实际采集Buffer在旧保护档下仍按90%提交的模型回归。全部测试、签名及冻结输入结果见 `../artifacts/BUILD_0.3.30.json`、`BUILDING.md`。

两端均覆盖安装0.3.30，选择新策略后断开重连。未安装或操作用户的OPPO Android11/vivo Android16；自动测试与模型接收器不代表双机画质/延迟实测。WebRTC AAR、原生库和服务端未改，无需部署后端。
