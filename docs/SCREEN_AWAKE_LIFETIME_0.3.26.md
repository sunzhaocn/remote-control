# 后台亮屏续期与断开释放复查（0.3.26）

复查0.3.25两端后台亮屏的持续性、失效恢复和断开后的系统息屏恢复。保留现有无障碍/悬浮授权入口、后台小紫点和手动关屏边界，视频与网络策略不变。本轮没有安装或操作OPPO Android 11/vivo Android 16手机，以下为源码检查和实际运行在应用资源驱动上的软件测试。

## 发现并修复

1. 主Activity在创建/恢复时无条件设置常亮，断开后从未清除。现在前台窗口与根视图的常亮标记也受当前会话计划控制；停止、断开、切后台或锁屏时清除。回到已断开的界面不会重新常亮。
2. 被控待机服务在后台注册凭据、重试信令时被算作需要亮屏。现在亮屏租约区分真实控制/共享或待确认请求与普通待机注册；断开后即使后台服务仍注册或重连，也不会因此常亮。终止状态中的残留会话ID也不授予亮屏。
3. 后台窗口只检查View.parent，已脱落、不可见或保留旧父引用时可能一直被当作健康。现在检查实际挂载和可见性，初次挂载有3秒宽限，失效后清理重建；每30秒重新声明KEEP_SCREEN_ON和根View标记。挂载/脱落事件触发检查，15秒定期检查继续兜底。
4. 移除前先丢失窗口引用，若系统移除失败，旧窗口可能不受后续清理追踪。现在先清除窗口的亮屏标记，保留句柄直到实际脱离；移除或显示锁释放失败时，即使已经没有会话也继续重试。旧句柄没清理完，不创建重叠的新窗口。保留旧ViewRoot父引用但已实际脱落的窗口可正常完成清理。
5. 单次电源/权限查询异常可能结束长期观察任务，或在断开时阻止执行清理。现在异常隔离，后续检查仍运行；无会话时不查询无关电源/锁屏/悬浮权限即可执行释放。显示锁状态未知时保守保留清理重试，不能报告“已释放”。

## 生命周期与限时

独立显示锁仍每30秒续期、单次120秒期限；15秒软件检查不依赖视频和触摸事件。显示锁提前失去或过期后可重新取得，健康窗口不反复创建。无障碍实例更换、前后台切换和权限撤销都会更新窗口归属。

前台标记、后台窗口、显示锁由同一个可测试的资源驱动管理。平台创建窗口时，驱动在调用attach前取得句柄，部分添加失败也能继续清理。诊断明确区分释放/重建待重试、窗口异常、已挂载和已释放；仍保存最近后台状态与上次系统灭屏记录。

断开后释放的是本应用的常亮请求，随后由系统按既有超时规则息屏。没有修改全局息屏时间，也不主动替用户锁屏。若其他应用本身请求常亮，其请求仍由系统独立处理。系统强停、主线程长期阻塞或厂商隐藏窗口/限制电源请求，不能仅靠软件测试保证物理屏幕一直亮着；窗口挂载和锁持有仍不等于物理面板测量。

## 验证与交付

新增资源驱动故障测试，模拟24小时后台续期、两端分别2小时后断开、提前失去/过期的显示锁、旧窗口仍有对象但脱落、隐藏、挂载超时、标记被清除、续期失败、创建/部分挂载失败、移除失败、清锁失败、前台标记清除失败、查询失败、新旧无障碍实例、授权撤销及延迟回调。前一版的纯策略检查扩展为28项；本版资源驱动24项。这些使用确定性时钟和平台替身，不是等候24小时或手机长期运行实测。

结果与签名/源码核对见 `../artifacts/BUILD_0.3.26.json`，复核 `../artifacts/verify-build-0326.py`。安装包 `../artifacts/SimpleRC-0.3.26-debug.apk`，两端覆盖安装后重连；无新增权限要求。WebRTC AAR与原生库不变，沿用相同AAR的0.3.20库回执，未部署后端。

手机验收：连接后两端分别切到其他普通应用，等待超过原系统息屏时间；再断开，确认紫点消失，返回主界面和留在其他应用时均允许系统正常息屏。诊断若显示仍在释放/重建，应保留相应状态及灭屏记录。实际机型上的持续亮屏和恢复息屏仍待完成此验收。
