日期：2026-10-13。用户确认本次实测版本为 0.3.1；最新授权允许更新后端，Android APK 仅本地交付。

## 相关要求与全局约束

一.9–10：先分析再修复，不编造手机验证；四.3/五.3/9/14：保存与在线区分、自定义持久化、随机刷新受模式约束、秘密使用 Keystore；七.5–8：前台服务与采集顺序、授权单用；九.6/十五.5–6：有限恢复、过期回调隔离、等待超时；用户允许普通页面上下滑动。禁止自动测试、模拟器、ADB 和手机操作。用户允许后端部署，但不得上传 Android APK。

## 已确认原因与修复

| 问题 | 已确认代码证据 | 修改 |
| --- | --- | --- |
| 页面挤压 | 实测 0.3.1 尚无滚动；0.3.2 只在表单内滚动，顶部/页尾和中央 weight 继续压缩表单 | MainScreen：普通页面整体单一滚动容器，取消中央 weight/嵌套滚动；远程画面独立；顶部显示版本 |
| 保存失败又恢复随机 | pendingFixedSave 等服务器 ACK 才保存；ERROR/超时重新加载旧模式 | SecretStore.putAll 一次加密提交 ID/code/mode，检查写入结果；先本机保存，再在启用被控时注册；网络失败不回退随机 |
| 保存就注册为可控制 | 保存时不检查是否启用待机，直接发送 REGISTER_FIXED | 未启用时仅保存，明确未上线；StandbyService 前台启动后才注册，匹配 ID 的 ACK 才显示确认 |
| 媒体缺少 Answer | setRemoteDescription 使用的观察者只处理 onCreateSuccess；实际设置成功回调 onSetSuccess，done 不执行 | 分离 SDP 创建和设置回调；设置远端描述后创建 Answer，设置本地描述后发送 |
| ICE 提前添加 | 收到候选直接 addIceCandidate，未等待异步远端描述设置完成 | 有限候选队列，远端描述完成后添加；会话结束清空 |
| 录屏启动顺序竞争 | Activity 启动服务后立刻开始采集，服务可能尚未 startForeground | 采集启动移入共享服务，在 startForeground 后执行；过期授权结果不启动采集 |
| 旧连接回调干扰新状态 | 多个异步 IO 任务共用 listener/pendingAction | 主调度器串行状态处理、连接 generation 检查、已连接 socket 复用、实际握手等待、单调时钟重连截止 |
| 待机约 45 秒断线 | 服务端仅 PongHandler 延长读取期限；客户端发 Ping；服务端未主动发送 Ping | 服务端 PingHandler 延长读取期限并回复 Pong，合法消息也延长期限 |
| 旧 socket 清理新配对 | removeClient 即使发现 client 已替换仍删除该设备 pairings | 只允许当前连接清理其配对映射 |

## 推测与缺少的证据

- 用户尚未提供本次手机失败的完整文字或发生阶段，不能将每次失败都归因于同一个缺陷。
- 没有直接观察手机输入渲染。本轮修正可确认的高度约束与校验逻辑，长验证码显示/编辑需原设备复测。
- 正常 TLS 校验的只读公网健康请求返回 204，只证明当前电脑可达，不证明手机网络/TLS/时间或媒体协商正常。
- 新版区分认证、TLS、格式、ID 占用及超时错误，显示错误代码；不关闭 TLS 验证，不记录验证码、签名或 SDP。

## 修复行为与影响

- “本机已保存”不代表服务器占用检查通过。启用被控后才检查实际占用与发布，匹配 ID 的 REGISTERED 后才显示注册成功。
- 本机保存的自定义模式跨网络失败保持，随机计时器不恢复。旧版本未成功保存的自定义值需重新输入。
- 切回随机时本机模式立即持久化；服务器固定 ID 在在线随机注册时释放，断网/未启用时不声称已释放。
- 本轮仍使用既有信令结构；后端补丁只改变读取期限和连接归属清理，不迁移数据库、不轮换密钥。
- WebRTC AAR 不变。原 STATE 中动态质量、统计、完整 PeerConnection 重建等缺口仍保留。
