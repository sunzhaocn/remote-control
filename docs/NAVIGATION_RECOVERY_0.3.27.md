# 0.3.27 导航后恢复与控制端返回保护

本次修复导航提示到期后没有新采集帧时遗漏清晰补帧，以及静止精修验证窗口小于编码和接收确认实际所需时间的问题。交互提示仍按控制端原始时间在350ms内到期，不由ACK、执行回调或视频画面续期；输入不会固定压到最低码率。

## 清晰度恢复

- 已接受的导航或位移提示重新允许一次静止补帧。即使返回被应用忽略、没有新画面，也在提示到期后重新请求；重复、乱序、过期提示不能重复触发。
- 静止状态保持应用依据真实拥塞和设备压力选择的分辨率、预算，同时切换原生编码策略以保持该尺寸，避免持续动态采样不足时还保留额外的原生缩小限制。操作或持续视频恢复优先帧率；有界试升和回退继续生效。
- 静止文字精修最多提交12次输入，容纳编码器预热/偶发丢弃；有QP时仍检查精修，无QP时仍需关键帧后的8帧。完成后立即停止额外输入。
- 文字精修试验最长5秒，容纳多帧精修和两次新接收反馈；静止保护档小步试升最长3.5秒，视频试升仍为5秒。缺反馈、超时、真实排队或处理压力仍回退和退避。
- 真实视频恢复无需持续造帧；补发相同纹理不参与媒体帧率判定，操作立刻取消精修。

## 只在控制端处理本地返回

使用AndroidX生命周期管理的OnBackPressedCallback，仅控制端已有会话且处于连接/已连接/重连、屏幕开启且未锁定时启用。控制端本地完成的返回操作（系统返回键或系统交给本应用的侧滑返回）在滚动一秒内累计100次才断开并退到后台。普通返回只提示从悬浮导航菜单断开。

悬浮导航中的返回/桌面/最近任务仍是远端命令，不计入本地退出计数；菜单断开直接执行。被控端不启用返回保护，也不修改无障碍服务、远端导航派发或系统输入钩子。断开、锁屏/息屏释放返回保护；切后台、会话变化、角色变化清除累计，Activity销毁释放接收器与回调。

**功能边界：该计数只适用于本应用接收到的返回。Home/上滑回桌面、快速切换和通知栏下拉属于系统操作，无法通过返回计数拦截。没有添加屏幕固定、设备所有者、遮挡系统区域或强制拉回前台。**

参考：[Android系统手势边界](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav)、[AndroidX返回回调](https://developer.android.com/guide/navigation/navigation-custom-back)。
