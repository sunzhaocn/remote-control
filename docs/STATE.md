## 当前策略

新策略默认：起始2Mbps、最小0.3Mbps、最大不设置应用上限（null，覆盖曾暂定6Mbps）；直接按屏幕比例长边1280采集，源输出及发送最高30fps，优先保帧率，硬件H.264可用时按双方profile协商、保留VP8兼容。默认策略保留库码率/编码顺序；下一会话才生效。没有统一WebRTC理论最大Mbps，实际受库/编码器/设备/网络限制。

平时控制画面没有传输指标叠层，指标留在通知；主动打开“诊断与策略”可查看。异常恢复提示仍可见。详细诊断缺字段显示未知，静止与滑动分别观察。

## 未完成项与不确定性

- 用户已反馈画面卡顿和RTT波动。此前缺帧率/实际编码器/冻结/缓冲数据，尚不能确定唯一瓶颈，不能承诺商业级流畅度；新策略及两条连接均未实测。
- 动态旋转/捕获范围/Surface同步、折叠屏、多窗口和全部IME坐标组合未完成或未验证；当前只初始几何有证据。
- 完整PeerConnection重建、媒体停滞识别、温度/网络驱动的完整质量阶梯未实现。
- 180天固定ID回收、完整保留词维护、成熟SQL迁移工具、全部配置项集中仍有缺口。
- 独立SDP指纹固定校验、单应用共享范围识别/拒绝、发送/播放缓存全部清空语义仍需补齐或核验；验证码复制未实现。
- 触控滑动是松手后完整手势传输并约600ms执行，非商业软件连续手指路径实时输入；无多指/底层注入能力。
- 全LAN/P2P/TURN/TCP/TLS/公网切网、第二人竞争、旧恢复令牌、防止权限撤销后抢控等组合未遍历。P2文字注入、60fps、几何叠层未授权。
- 两条连接共享物理Wi-Fi和CPU，不保证视频拥塞时触控完全无影响；选中非relay不等于LAN，当前P2P明确写未确认LAN。
- 屏幕亮锁为已废弃平台API，厂商仍可能杀进程/限制锁；不修改全局超时、不唤醒或绕过手动锁屏、不静默恢复录屏。
- 音源可能因DRM/捕获策略不可用；音画同步、听感和所有停传/恢复组合仍待人工验收。

逐条实现边界见 REQUIREMENTS_TRACEABILITY；实际0.3.4结果见DEVICE_TEST_0.3.4，视频分析与下一次对照见VIDEO_DIAGNOSTICS。

编译与诊断的边界补充：硬件广告能力不保证所有厂商实际初始化成功；对支持profile的能力协商保留VP8，但运行时硬件初始化失败后重新协商不同codec的完整降级链尚未实现。独立控制未实机、无应用码率上限并不解除库默认/codec/device限制。测试结束后手机端项目诊断文件未再次访问清理，见DEVICE_TEST_0.3.4。
