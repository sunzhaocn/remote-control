## 编解码与兼容性

- 互动模式硬件编码器请求 `priority=0`、`latency=1`；H.264/H.265 显式 `max-bframes=0`，Surface 输入声明最大 60fps。保留支持列表与兼容 codec。
- 硬件原始输入积压优先最多 2 帧。满队列且连续 200ms 未有输出进展时，回退最多 3 帧，防止忽略低延迟参数、需要第 3 帧输入的编码器停住。诊断显示实际 2/3 帧上限；这些只约束 Java 记录的在途输入，不代表芯片内部总缓冲。
- 硬件编码配置拒绝可选参数时，释放并重新创建同名编码器，移除可选参数后重试。硬解仅在 Android 11+ 且能力明确支持低延迟时请求该模式；配置拒绝时同样重建回退。`start()` 失败继续走上游失败/兼容处理，不声称所有启动失败都能成功回退。
- 编码器报告实际 `latency` 才展示数值，缺失显示未知；支持能力或配置接受不等于设备实测兑现。首次初始化失败不显示失败硬编的名字。
- 修复编码配置输出 buffer 未归还的问题；异常输出缺少输入元数据时释放 buffer 并请求下一次关键帧，避免直接崩溃。
- 未随意丢弃已编码 H.264/VP8 参考帧，未缩短硬解输入等待或强制 flush。输入满时丢弃的是尚未编码的原始帧；丢压缩参考帧会破坏后续解码。

## 渲染与反馈

渲染端保留上游单帧待显示位置，收到新帧替换旧帧并正确释放引用。互动模式合并渲染任务，避免每帧都向 Handler 投递空任务；结束/清屏释放待显示帧，渲染器释放后重建会重置唤醒门闩。已解码帧在本机等待超过 150ms 时放弃该帧，年龄来自本机单调时钟，不把远端时间戳直接与本机时钟相减。

诊断分别显示 GPU 提交帧率、显示前等待、GL 绘制和换缓冲耗时，以及原始编码积压/峰值/丢帧、硬解输入峰值、渲染替换/过期丢弃。GPU 提交不等于显示屏已经呈现，所有阶段耗时也不等于端到端画面延迟。没有新样本时耗时显示未知。

控制端每秒反馈本机等待、绘制、换缓冲和解码均值。反馈只含汇总数值，绑定会话/序号/单调时效、最多保留 3 秒，控制队列达到 2KiB 时跳过，不能堵住触控。两端的旧会话编解码器统计各自保存会话对象，换缓冲回调使用提交该帧时的对象。

## 视频预算与恢复

新策略采集长边最多 1280、源适配及发送最高目标 60fps，默认策略继续 30fps。起始视频上限 2Mbps，最高 4Mbps。可用带宽存在时，预算取 80% 再扣除音频 128kbps、控制余量 192kbps，视频最小 150kbps。这是工程预算，没有物理网络独占保证。

每秒采样；控制应用往返相对 20 秒滚动低值增加 80ms、媒体 RTT 增加 100ms、丢包超过 3%，或显示前等待超过 60ms 时，上限最多每 2 秒乘 0.65。三个健康已知网络样本后每次恢复 15%，没有网络数据不主动抬高上限。选中 ICE 候选对真正改变时重新建立基线，稳定较高延迟会逐渐替换旧低值。

两个样本持续 CPU 受限、编码超过 20ms、GL 绘制超过 16ms、换缓冲超过 35ms、解码超过 25ms 或显示前等待超过 60ms，就缩小发送长宽各一半并降至 30fps。十个有耗时数据的健康样本才恢复；低于 900kbps 保持 30fps。换缓冲独立参与判定，避免 GPU 阻塞时“最新帧等待很短”掩盖显示压力。阈值仍需根据实机调整。

增加控制通道每两秒的实际应用探测和匹配操作 ACK 耗时；ACK 测量抬起/取消或导航的提交到系统回执，不是最初按下到显示变化的时间。继续保留独立控制 PC、无序零重传 MOVE、可靠 DOWN/UP/CANCEL、单指连续无障碍手势和 700ms 失联释放。

## 服务器与验收边界

当前检查后端健康 204，后端 CPU 0.05%、Coturn 0.01%，约 912MiB 可用内存；eth0 两个发送队列已用 fq_codel。没有活跃双机/TURN 压力测试，不能据此确认中继性能。现有信令能转发控制连接协商，反馈走客户端 DataChannel；服务器发布独立新版 APK，无需变更运行后端或数据库。

构建、34 项确定性单元测试、签名和四 ABI 原生库一致性已通过；完整公网下载与本地/服务器哈希及长度一致，GET/HEAD200、首尾Range206内容一致，见 STATE 和发布回执。自动测试覆盖无输出编码器的有界逃生、恢复/旧回调隔离、并发帧合并、渲染器重建、缺失统计、网络切换、GPU 换缓冲阻塞及输入结束动作保留。测试中的编码器/手势是状态模拟，没有替代 Android MediaCodec、EGL 或系统手势实测。

仍须双机确认：60fps 实际采集/编码/显示、硬解低延迟是否生效、连续拖动/快速滚动/连点、公网 P2P/TURN/切网、权限中断松手、内部音频及音画同步。没有声称已经达到 ToDesk 体感，也不承诺所有网络绝对不卡。

## 本次核对的官方接口

- [Android MediaFormat 延迟、优先级与帧格式](https://developer.android.com/reference/android/media/MediaFormat#KEY_LATENCY)：延迟以帧计，是否兑现须读编码输出格式；优先级提示不保证性能。
- [Android 低延迟解码能力](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities#FEATURE_LowLatency)：仅在支持该能力的解码器上请求低延迟。
- [Android 连续无障碍触点](https://developer.android.com/reference/android/accessibilityservice/GestureDescription.StrokeDescription#continueStroke(android.graphics.Path,%20long,%20long,%20boolean))：正常授权的连续手势路线；本项目仍是单指。
