# 后台亮屏保护（0.3.25）

用户确认：控制端切到其他应用后会按系统超时息屏；两端设备为 OPPO Android 11 和 vivo Android 16。旧版已有前台窗口亮屏标记和后台 SCREEN_DIM_WAKE_LOCK，源码与先前的单元测试未能证明这些请求在这两台手机的后台持续生效。本版增加独立后台窗口与可检查的运行状态，不把“请求了唤醒锁”当作已完成手机验证。

## 实现

- 前台由实际 Activity 窗口与根视图保持亮屏；切到后台后，连接所属的服务租约继续生效，独立窗口负责窗口级亮屏请求。控制端、被控端以及重连均覆盖；不依赖是否有触摸或视频是否持续出帧。
- 已连接的无障碍服务提供 TYPE_ACCESSIBILITY_OVERLAY；没有无障碍连接时，使用已获授权的 TYPE_APPLICATION_OVERLAY。控制端新增“允许后台亮屏”入口，带到 Android 的悬浮显示权限设置。Android 11 可能先显示应用列表，需选择 SimpleRC。
- 窗口为屏幕边缘 6dp 小紫点，FLAG_KEEP_SCREEN_ON、NOT_FOCUSABLE、NOT_TOUCHABLE；不接收点击或键盘，不生成任何假触摸。Android 12+ 的透明度按系统实际触摸遮挡阈值取更小值；同进程只保留一个后台窗口。
- 统一的 SCREEN_BRIGHT_WAKE_LOCK 作为显示保护补充，每30秒续期、单次120秒上限；独立15秒检查不受视频统计/输入回执影响。取消旧的分散 DIM 显示锁及8分钟显示续期依赖，CPU/Wi-Fi保护仍归原服务管理。
- 服务实例持有租约；最后一个当前会话服务释放、角色切换、连接结束或租约归属过期时，撤销后台窗口与显示锁。旧服务销毁不会移除新会话的租约。无会话的后台待机不保持屏幕常亮。
- 电源键/系统关屏后立即移除显示保护，不自动点亮或解锁。SCREEN_OFF 不能区分电源键、系统超时和厂商策略，因此诊断不把收到该广播一律认作“用户手动锁屏”。被控端共享仍在关屏后按既有规则停止。

## 授权与诊断

两端覆盖安装后重连。控制端在“后台运行设置”中点“允许悬浮显示以保持后台亮屏”，或连接页面的“允许后台亮屏”，在系统设置中允许 SimpleRC。此授权由 Android 要求用户手动授予；允许后台运行/省电豁免不等于已经授予悬浮显示。被控端可复用已经启用并连接的无障碍服务，无需为该路径再申请悬浮权限。

后台运行设置、诊断、通知均显示保护状态；缺权限、窗口建立失败、等待挂载不会被显示成“后台保护就绪”。返回应用后可看“最近后台状态”；若确有灭屏，则“上次灭屏记录”保存灭屏前的保护状态和时间，应用重开后仍能查看。异常写入系统日志，不再静默吞掉显示请求失败。

“窗口已挂载”和“显示锁已持有”分别是应用观察到的状态，并不测量物理面板，也不保证厂商没有额外限制。敏感页面可由系统隐藏应用悬浮窗。实际后台持续亮屏须在两台手机上超过原自动息屏时间验证；本轮没有安装、操作或实测手机。

## 验证

新增24项策略与服务租约测试，覆盖前台/后台切换、无障碍/悬浮窗口选择、缺少/撤销授权、无障碍重绑、屏幕已关闭、锁屏/解锁、旧/新服务归属、角色切换、待机与断开释放，以及大量视频/输入统计不改变归属。原视频恢复和触控测试保留。完整结果见 `../artifacts/BUILD_0.3.25.json`；APK `../artifacts/SimpleRC-0.3.25-debug.apk`。WebRTC AAR和原生库未变，未部署服务器。

双机验收：两端授权并连接后分别切到桌面或其他普通应用，确认小紫点出现；不触摸等待超过系统原息屏超时；返回诊断查看最近后台状态；断开后紫点移除并恢复系统正常息屏；手动电源键仍关屏，被控端停止共享。若仍自动息屏，请提供本版诊断中的上次灭屏记录，而不是仅凭当前画面推断锁是否生效。
