# 控制端提前触发压缩（0.3.21）

0.3.20的导航压缩在被控端实际派发系统动作前触发，仍会等待远端处理和旧手势释放。本版将触发点移到控制端发送操作时，不等被控执行、翻页动画或ACK。

点击、长按、返回、主页和任务切换，在控制端准备好有效操作后，先发送VIDEO_ACTION压缩提示，再发送实际输入。提示同时走touch-latest实时通道和control可靠通道：实时副本绕过可靠输入排队，可靠副本排在操作之前。双方共用这次操作的sequence，但画质提示不推进lastControlSequence、不注入输入、不生成输入ACK。

被控端收到有效提示就应用交互档；导航实际执行前的旧画质回调已移除，执行和回执不会重新续期。350ms期限从控制端原始时间计算，扣除网络年龄与时钟不确定度。两份相同提示去重，旧序号、过期提示不重开模糊。操作被拒绝或排队时，提示也只影响自己的短期限。

滑动沿用0.3.20的VIDEO_MOTION：控制端识别实际拖动后，在可靠DOWN之前发送，后续真实位移续期；静止心跳不续期、结束水位防止乱序重开、220ms寿命保持。持续视频帧不会触发或延长压缩。正常85%/最长2160、交互长边360/350kbps、30fps上限、VSync、CPU保护及有界清晰补帧保持。

这里提前的是发送端编码策略请求。实际压缩和新画面传回仍需要网络传输；控制端没有叠加人为模糊滤镜。导航菜单按钮在点击确认时发出指令，拖动在超出触摸阈值时识别；不将移动悬浮菜单等本地界面操作当成远程输入。

自动回归新增动作提示重复/乱序、原始期限、动作提示提前于输入执行、移动结束不续期、短提示与输入期限分离。结果见 `../artifacts/BUILD_0.3.21.json`。WebRTC AAR与0.3.20逐字节相同，沿用该相同AAR已有调度/采集桩/队列回执，本次未重建AAR或重跑这些不变库的行为检查。

两端覆盖安装 `../artifacts/SimpleRC-0.3.21-debug.apk`，选择“新策略”后重连。没有安装或测试手机，仍需双机确认可见切换时机及字体清晰度。服务端未修改，无需部署。
