# 0.3.33 精修中止分类与设备观测

按用户对0.3.32的复核处理最小集：修正文本失败分类与失败时带宽基准，补充设备观测数据。只改应用层，保持固定30fps、正式版90%/对照88%/回归80%宽高；不新增性能档，不改AAR、原生库、权限或后端。

## 1. 只将应用后的验证超时计入文本暂停

`VideoRecoveryProbe.rollback`增加显式`qualityFailure`标记。只有文本试验已记录applied、到了验证期限仍未确认，才调用`textGate.failed`。该计数表示“精修应用后的验证超时”，并不能单凭它证明QP必然不可达。

以下中止不计入文本的两次失败暂停：新拥塞、设备耗时/吞吐压力、参数始终没有应用、用户操作/真实内容恢复、路径/尺寸变动引起的取消。应用前超时、压力中止采用文本专用3秒安全等待；应用后验证超时保留10秒文本冷却。正常视频试验自身的失败回退、观察期和验证锁保持。

压力判定集中在活动/超时处理之前：即使某次统计报告正好落在6秒截止时且带有拥塞或设备压力，也按压力中止处理，不先记为文本验证失败。用户取消仍先释放试验。文本计数不会污染连续视频恢复。

## 2. 失败基准取最近的新鲜观测

`observe`先更新当前带宽观测，再处理压力与超时。独立50ms活动定时器触发超时时，使用最近1500ms以内的BWE；缺失、无效或过期就按未知处理，不回退使用试验开始值。`Trial.capacityKbps`保留为开始时的诊断信息，不参与恢复门槛。

例如两次试验开始时都是5Mbps，但各自失败前最新BWE为1Mbps，则暂停后的恢复门槛为2Mbps；反向从1Mbps起步、失败时已到5Mbps，则门槛为10Mbps。若失败时没有新鲜BWE，沿用已定义的未知带宽恢复条件：新的有效估计至少4000kbps。实际路径变化/新会话继续清除文本暂停。

这里的“失败时”是故障处理时最近可用观测，不是逐包实时带宽测量。数据新鲜度和未知回退均有测试覆盖。

## 3. 编码耗时分布与队列丢帧增量

- 现有`totalEncodeTime/framesEncoded`差分只能得到统计区间均值。因此本次新增的是**近60秒编码耗时区间均值的P50/P95**，不是逐帧编码耗时P50/P95，更不是端到端延迟。默认统计周期500ms；采用最近秩法，最多120个真实新样本，并显示样本数。
- 只有新统计时间戳且encoded frame计数前进、均值有效时才加入样本；重复报告、静止无新编码帧不补零。无新有效样本超过3秒时显示未知。会话、流、编码器、codec或编码尺寸变化，以及encoded frame计数回退、倒序时钟、超过3秒采样中断，都会重建分布基线，避免混入不相干成本。
- 原生`encoderDropped`新增相邻有效快照的差分及区间毫秒数。初次采样、编码器/会话变化、计数器回退和超过5秒间隔显示未知；有效区间无新增丢帧显示0。它是本地编码队列计数增量，不等于整条链路所有丢帧。
- 数据显示在被控端诊断，并通过已有senderPolicy摘要供控制端查看；消息格式、768字符边界保持。这些指标只供观测，不参与新性能档或像素/帧率调节。

## 4. 保持的边界

`protected=scale>1.001`改名为`hasPressureHistory`并补注释，明确这是预算探测的证据档；非文本状态文案改为“小步预算探测”，不再暗示真实像素正在恢复。

过渡期关键帧可能使静止QP区间均值偏高这一观察项，本次不调整：保留0.3.32的500ms静止门槛、最近3秒H.264样本与2.5Mbps估计预算条件。待双机QP分布与关键帧时序数据后，再决定是否要求连续样本或排除含关键帧区间。

仍然保留：精修只抬不降已有上限、12次/200ms有限补帧、应用刷新10秒3次预算、严重压力500ms再次退降、接收shape/decode/swap验证。真实带宽/排队压力仍可让正常预算退降；不能把维持精修上限理解成忽略拥塞。设备持续过载目前仍依赖有界队列丢帧，尚未实现一次性性能档。
