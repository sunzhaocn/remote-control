# 0.3.12 全面检查与重构

本轮以 0.3.11 为基线，检查 Android 会话、授权、信令、触控、视频、音频、资源释放，以及 Go 后端的配对、限流、租约和并发状态。检查发现缺陷，先修复，再按职责提取独立模块；没有重写传输协议、替换底层 WebRTC 或升级全部依赖。

## 已修复的问题

| 范围 | 问题与处理 |
| --- | --- |
| 授权 | 旧录屏授权可能确认后到的新请求。现在绑定发起授权的会话，防止重复发起，确认发送成功后才启动对应共享；确认回执另有握手超时。 |
| 凭据 | 拒绝连接或确认超时后，随机凭据刷新任务未恢复。现在沿用原到期时间，并提前 15 秒续期。 |
| 生命周期 | 角色切换取消尚未取得 ID 的连接；旧服务/旧会话回调不能清理新会话；复用共享 Service 时按所属会话消费新授权；WebSocket 正常关闭只报告一次。 |
| 拖动 | 仅编码分辨率改变也会重启触控协程。现在真实捕获几何与显示像素分开，等比降画质保持当前手势，真实旋转或视口变化仍取消。 |
| 输入时效 | 到达后排队曾重新获得 2 秒时效。现在保留包含时钟误差的原始截止时间，点击和导航实际执行前再检查。实时 TOUCH 仍使用原 700ms 校验。 |
| 音频 | 两条消息路径上旧 START 可能覆盖新 STOP，旧失败回复可能取消新重试。现在请求序号和回复版本分别校验；本机撤权仍立即生效。 |
| 回执 | 没有新输入时，超过 3 秒的旧 ACK 仍能更新结果。现在收到 ACK 时再次校验有效期，并保持有界、一次性匹配。 |
| 资源 | 采集启动中途异常时，局部资源尚未登记；单次 native close 异常也会跳过后续释放。现在资源创建后立即归属会话，停止时逐项清理，关闭幂等。 |
| 后端限流 | 原代码失败后计数，但请求前没有拒绝封禁中的验证。现在在验码之前检查，计数和 TTL 原子写入，可信代理配置明确区分实际客户端 IP。 |
| 后端配对 | 凭据哈希与在线所有者来自不同存储，固定/随机同名和清理可能错配。现在使用不可变的已发布记录绑定二者，清理校验所有者，Redis 操作移出全局会话锁。 |
| 后端状态 | 确认与超时可能竞争，未确认会话也可转发协商消息。现在状态转换和删除原子化，只允许已确认会话转发；确认消息发送失败统一撤销和释放租约。 |

## 重构后的边界

- `SessionAudio` 管理音频轨道、启停、请求超时；`AudioControlState` 独立处理消息顺序。
- `PendingInputAcks` 管理回执容量、时效和去重。
- `CaptureConsent` 绑定系统授权与会话；`CredentialRefreshSchedule` 管理凭据续期时间。
- `PeerClockEstimate` 提供可测试的单调时钟计算；`RemoteViewport` 分离真实触控坐标空间和视频显示尺寸。
- 后端 `pairing.go`、`session.go`、`validation.go` 分别处理凭据发布、会话状态转换与验证限流，主处理函数保留协议路由。

模块提取保持既有用户流程、LAN/P2P/TURN 选择、视频自适应参数和双通道触控方案。仍使用单个信令服务进程；SQL 与 Redis 不构成跨库事务，持久化失败不激活新发布记录，临时随机占用依靠 TTL 释放。

## 已验证与边界

Android 最终构建 55 秒成功，140 项单元测试零失败/错误/跳过；lint 零错误、21 项非阻断提示，未全局禁用检查。包括新增的授权、刷新、角色状态、显示空间、时钟、输入排队、音频乱序和 ACK 回归。APK v2 签名有效且与 0.3.11 同证书，AAR 与四 ABI 原生库保持一致。

安装包：`../artifacts/SimpleRC-0.3.12-debug.apk`，versionCode 15，72,116,022 字节，SHA-256 `673becbbe8fbed5213886c68d2d7a490e01480f4ff50209185353c7d895c2ce4`。完整源码、测试与签名回执见 `../artifacts/BUILD_0.3.12.json`；最终构建前冻结的输入哈希也已核对。

后端 22 项测试、`go vet` 和 Linux/amd64 构建通过。测试使用进程内 Redis/Lua 模拟、SQL 仓储替身和本机 WebSocket；不能当作真实 PostgreSQL/Redis、线上迁移或公网会话验证。当前 Windows 构建环境没有 race detector 所需的 C 编译器，未声称并发检测器通过。详见 `../server/REFACTOR_REVIEW.md`、`../server/dist/BUILD_REVIEW.json`。

上述本地验证完成后，2026-10-16 已按用户指示部署配套后端。实际代理对端验证为 `::ffff:172.19.0.1`，配置仅信任 `172.19.0.1/32`。公网 8 项配对/会话检查与隔离环境 2 项限流检查均连接真实 PostgreSQL/Redis 并通过；TURN UDP/TCP/TLS 公网双向回传通过。临时测试数据已清理，备份与回滚路径见 `DEPLOYMENT.md` 和 `../artifacts/DEPLOYMENT_0.3.12.json`。信令检查使用合成 SDP/ICE，不是实际媒体；仍未运行手机安装、设备控制、实际音画同步或端到端延迟测试。

## 用户最后测试

两端安装 0.3.12 后重连。先复测点击、快滑、长按、导航、旋转和连续拖动，再测试弱网降画质时拖动不中断、音频快速开关、断开重连、被控端拒绝请求后连接码继续刷新、授权弹窗期间请求超时后不能误确认下一请求。LAN/P2P/TURN 对照步骤沿用 `LOW_LATENCY_0.3.11.md`。

“自动检查通过”不等于所有设备和公网组合均无问题；本轮没有将原有未验证事项标记为已完成。
