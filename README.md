# SimpleRC

## 0.3.38

新策略以 60 fps 为默认目标，默认使用 MediaCodec 自动选择，也可以在诊断与策略中选择仅 H.264。画质支持自动、清晰 2 Mbps、高清 8 Mbps、原画 20 Mbps，以及 1～500 Mbps 自定义上限。界面显示双方确认的实际上限，WebRTC 根据链路调整实际码率。

帧率可选 30、60、90、120、144 和 165 fps。应用按实际编解码器、画面尺寸和显示能力确认档位，并显示当前生效档。 尚未确认支持的选项会灰色禁用。持续设备压力触发降档时，本次会话会限制该编码器和尺寸下的高档。严重拥塞时先降低输出尺寸和帧率，链路恢复后再恢复原档。

[下载 Android APK](https://github.com/sunzhaocn/remote-control/releases/tag/v0.3.38)

本轮实测覆盖一台实体 Android 设备，接收端分别为 Android 模拟器和独立 Windows 接收器。双实体机互控和更多机型尚待验证。

- 单台 Android 真机以 1272×2800、H.264、32 Mbps 上限在局域网发送，固定显示 60 Hz。独立 Windows 接收器的 120 秒平均组帧率为 60.04 fps，最慢 10 秒窗为 59.85 fps，最长组帧间隔 54 ms，实际平均约 23.47 Mbps。另一次显示设为 120 Hz 的压力轮出现了约 500 个 RTP 包的缺口和 2.06 秒空档。
- 真机和模拟器的签名包联调中，媒体和独立控制的私网 UDP RTT 分别为 4 ms 和 6 ms。双向 4 Mbps 与 40 ms 限速下，后 12 秒仍观察到 10 次画面更新，触控命中，解除限速后画面恢复。画面采样间隔约 1.2 秒。
- 单独限制接收端视频 RTP 到 2 Mbps 时，输出降到 636×1400、24 fps。稳态为 23～25 fps，最初有效画面空档为 3.76 秒，另有一次 1.32 秒空档，解除限速后约 23 秒恢复到原尺寸和 60 fps。接收器等待关键帧恢复参考链，保留的 3,490 个帧全部通过严格 H.264 解码。
- 模拟器只确认了当前会话的 30 fps 档。横竖屏十个触控标记的最大误差为 3 像素，320 和 360 dp 布局及大字体通过。真机发送压力、独立组帧以及真机与模拟器的画面和触控分别验收。
- Release 源码回归共 667 项测试通过，Android Lint 通过。安装包从发布提交的 Android 源码和随附 WebRTC AAR 构建。
